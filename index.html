Sequential search checks documents one by one. Inverted index uses the stored term → document relationship built in advance. Building the index takes extra time and memory up front; it can reduce repeated document scanning during queries, but is not automatically faster in every situation.

Complexity

Sequential Search: repeated document scanning as the collection grows — every query re-reads every document.

Inverted Index: index construction requires extra work and storage up front. After construction, term lookup can access the posting list directly if a fast dictionary (e.g. hash table) is used — but in a simple array-based C implementation, finding a term may still require scanning the index entries one by one.

Index Storage ≈ O(T + P)  where T = number of unique terms, P = total number of postings.

Note: an inverted index does not automatically give O(1) lookup — that depends on the dictionary structure used to store the terms.

C Implementation Connection

The same concept maps directly onto a C implementation using structures, character arrays, integer arrays, functions, and loops:

struct IndexEntry {
    char term[30];
    int docIds[20];
    int count;
};

struct IndexEntry index[MAX_TERMS];
int indexSize = 0;

/* Example: add a document id to a term's posting list */
void addPosting(char *term, int docId) {
    for (int i = 0; i < indexSize; i++) {
        if (strcmp(index[i].term, term) == 0) {
            index[i].docIds[index[i].count++] = docId;
            return;
        }
    }
    strcpy(index[indexSize].term, term);
    index[indexSize].docIds[0] = docId;
    index[indexSize].count = 1;
    indexSize++;
}

This simulator runs in HTML/CSS/JavaScript for visualization only — the data structure logic and terminology match the C project (struct + parallel arrays), not a Java or Python implementation.

Limitations
  • Basic term matching only
  • Does not understand the meaning of sentences
  • Does not automatically rank results
  • Requires extra memory for the index
  • Index must be rebuilt when documents change
  • This is an educational simulator, not a complete commercial search engine
  • A simple C implementation has practical size limits (fixed array sizes)
